# AgentForge implementation notes

## Decisions
- Task book v3 takes precedence over older sections of the development plan.
- Import the pinned base locally; retain this repository's origin and document history.
- Tier 1 uses one runtime process; MongoDB is the production persistence backend.
- Restricted host tools default to a dedicated workspace; Docker isolation arrives in T10.
- T15.A1+A2 (ADR-0014): every /api request needs a session; identity comes only from the HttpOnly cookie resolved server-side. scrypt instead of argon2 (no package proxy on the deploy server; the hash carries its own parameters). Ownership is an `owner_id` on every row with (owner_id, id) uniqueness, "" meaning shared-read (only the built-in agent). Mismatches answer 404, never 403. The first account is created explicitly from ADMIN_USER/ADMIN_PASSWORD; owner-less legacy rows bind to it at startup. Origin checks accept X-Forwarded-Host; Vite proxy keeps Host (changeOrigin: false) or every dev write looks cross-origin.
- ADR-0015: the login wall moved to the first turn that needs an account. An anonymous visitor gets its own `guest_` owner id (same ownership filters, nothing downstream changed) and may run GUEST_TURNS real turns, site-wide capped per day; installation routes stay 401. Signing in adopts the guest's transcript; unclaimed trials are pruned after GUEST_RETENTION_HOURS; GUEST_TURNS=0 restores the full wall.

- ADR-0016 (first half of T15.A3): a sandbox lease now carries the account that claimed it and keeps it across `release()`, so knowing a session id no longer reaches another account's container or files; one account may hold `SANDBOX_MAX_PER_OWNER` (default 4) claimed sandboxes; `/health` reports owners as a digest only. Workspace directories stay flat (`sandboxes/<id>`) because a warm container is created before its claimant is known and its bind mount cannot be re-pointed. Encrypted MCP credentials, snapshot ownership and the migration rehearsal are still open.

## Backlog
- Email accounts (ADR-0018) replaced the phone door, but the phone endpoints still exist and the interface no longer offers them. An account created before this change therefore has no way back in from the UI: build a migration path (bind an address from a signed-in session, or an operator-side move) before this reaches real users. Deliverability is now the operator's problem too — SPF, DKIM and a sane From address decide inbox versus spam, and a throttling provider is indistinguishable from a wrong address from the client's side.
- Neither door has a recovery path: a reassigned address or carrier number means a lost account. The daily send counters live in Mongo and the password-failure tracker is per-process, so a multi-instance deployment wants a shared rate-limit store. Consider a second factor or recovery codes before accounts hold valuable data.
- Next platform security milestone (partially done): T15.A1+A2 shipped (ADR-0014) plus the anonymous trial (ADR-0015) and sandbox lease ownership (ADR-0016). Outstanding: per-user workspace roots, encrypted MCP credentials, snapshot ownership, the ownership migration with a dry run and rollback rehearsal, and the two-browser security acceptance (T15.A4) before true multi-user exposure.
- T10-T12: Docker isolation, warm pool, circuit breaker, GridFS snapshots.
- T13-T14: Complete platform endpoints and frontend wizard/approvals/trace/Inspector. The agent wizard and conversation binding shipped 2026-11-02; the standalone trace page/replay, DevTools event stream and per-conversation cost display are still open.
- Legacy MCP ownership: rows written before accounts existed carried an empty owner and were treated as shared, so the config refresh added owned twins with the same id — two rows, double discovery, double tool registration. Startup now settles them onto the operator account (ADMIN_USER, else the first account) and `run_servers` dedupes ids; keep that rule in mind before adding another auto-attach path.
- T15-T20: Skills, delegation, benchmark suite, hardening, full-stack deployment.

## Verification
- 2026-11-03 Email sign-up replaces the phone door (ADR-0018): the login dialog defaults to an email tab, and verifying a new address creates the account — no registration page, and the send endpoint still refuses to reveal whether an address is known. The code lifecycle from ADR-0017 moved into a channel-agnostic `verification_codes` collection (`identifier` + `channel` + `purpose`) so SMTP and SMS share one set of rules: salted digest, five-minute TTL, five wrong answers kill it, per-address cooldown plus per-address and per-IP daily budgets in separate counters, and a failed send rolls the row and both counters back. Two correctness fixes came out of the move: a consumed code is now marked `consumed_at` instead of deleted (deleting it also deleted the cooldown record, so a successful sign-in could immediately request another message), and verification only matches a row that has not been consumed, which matters when two codes share a second. `mail.py` speaks SMTP through `smtplib` (STARTTLS / implicit TLS / plain for a local sink) in a worker thread, with a console channel and a development-only echo; a named-but-misconfigured provider makes the endpoint answer 503 instead of printing codes into a log. `email_address.py` normalises to lower case and masks on the way out, `users.email` carries a sparse unique index, usernames are derived from a digest, and binding an address another account owns answers 409. Frontend: `verification.tsx` replaces the SMS module, `EmailBindDialog` replaces the phone dialog, the sidebar shows `a***@example.com`. 405 backend tests pass (21 new: message construction, signature-free config checks, SMTP refusal wrapping, normalisation, one-account-per-address, channel isolation, consumed-code cooldown, two 422 paths, bind conflict); ruff, tsc, i18n, ESLint and the production build pass. End-to-end against a local SMTP sink: the API answered without `debugCode`, the sink received a real message with the code and Chinese subject, verification created `a***@example.com` and set the cookie, `/api/auth/me` returned the masked address, and the same code answered 400 `expired`. Nothing was deployed.
- 2026-11-02 Phone sign-up and SMS codes (ADR-0017): the login dialog now defaults to a phone tab and a new number becomes an account the first time its code verifies — there is no separate registration page. `POST /api/auth/sms/code`, `/api/auth/sms/verify` and the signed-in-only `POST /api/auth/phone` share one code lifecycle in `auth.py`: six digits stored only as a salted SHA-256 digest, single use, 5-minute TTL row, five wrong answers kill the code, and the row is written before the provider call so two racing sends cannot both pass the cooldown (a failed send rolls back the row and both daily counters). Three send-side gates — per-number cooldown, per-number daily cap and per-IP daily cap — keep the public endpoint from burning the SMS budget, and `SIGNUP_OPEN=false` closes self-registration without spending a message. `sms.py` signs Tencent SendSms (TC3-HMAC-SHA256) and Aliyun Dysmsapi (RPC HMAC-SHA1) with the standard library over the existing httpx dependency; signature helpers are pure so they are tested without a network. A console channel logs the code, and only with `SMS_DEBUG_ECHO=true` returns it to the browser; a named-but-misconfigured provider yields 503 instead of silently printing codes. Numbers are normalised to E.164 in `phone.py`, given a sparse unique index, and masked everywhere they leave the server; phone accounts have no password, so `authenticate()` keeps spending the dummy scrypt hash to avoid a timing oracle. The ADR-0014 Origin check now covers every unsafe method including anonymous ones (login CSRF), and both login paths converge on `finish_login()` so a phone sign-up still adopts the guest trial transcript. Frontend: countdown, localised error codes, dev-echo hint, sidebar masked number / bind action. 384 backend tests pass (35 new: signature vectors, normalisation, cooldown/daily/attempt/rollback/consumption, endpoint status codes, phone-taken conflict, guest bind refusal), ruff, tsc, i18n, ESLint and the production build pass. curl against the console channel confirmed send→verify→cookie, and real-browser checks confirmed phone sign-in, the sidebar number and the bind dialog. Browser helpers for this run were temporary (`/tmp/check_phone_*.py`), not committed.
- 2026-11-02 Agent creation wizard (T14): `/agents` now lists saved definitions and a three-step wizard (basics → capabilities → limits) creates, edits, duplicates and deletes them; `GET /api/tools` serves the runtime's real tool catalogue so the form cannot drift from the registry, and create/update share one validation path (unknown tool or unregistered provider → 422 at save time). A conversation is bound to the agent that started it: the picker locks once a message exists, reopening a session restores the agent it used, and a request carrying `agentIds` takes model/tools/limits from the definition (the header then says "set by the agent" instead of offering a model switch). The built-in `default` stays shared read-only — copy it to change it — and visitors may browse and run it but get 401 on any write. Two data bugs surfaced while testing: a cached validation registry raised "Duplicate tool" the second time the same MCP server backed an agent (a fresh registry per validation now), and legacy MCP rows left with an empty owner by a pre-account boot coexisted with their owned twins, so every server was discovered twice and attached twice (startup settles them: bind the only copy, drop the stale twin; `run_servers` also dedupes ids). Agents with no ADMIN_USER configured now bind legacy rows to the first existing account instead of leaving them ownerless. 349 backend tests pass (13 new: CRUD, reserved id, cross-account 404, MCP double-backing, duplicate-row dedupe, guest write refusal); ruff, tsc, i18n, ESLint and the production build pass. Real browser: create → list → edit → "use" → one real turn with the stored agent (request carries `agentIds`, reply follows its system prompt, bubble signed with the agent name), console clean.
- 2026-11-02 Sandbox lease ownership (ADR-0016): the pool records the claiming account on the lease and keeps it when the lease is cached, so a second account presenting the same session id is refused instead of resuming onto that conversation's files; the run path takes the owner from the run lock, `/api/sandbox/exec` attributes its disposable container to the caller, `discard` refuses a lease that belongs to someone else, and pool status hides accounts behind an 8-hex digest because `/health` is public. A per-account cap (`SANDBOX_MAX_PER_OWNER`, default 4) stops one user from taking the whole pool. 336 backend tests pass (4 new pool tests plus owner assertions in the exec and session-delete paths), 1 skipped; ruff clean.
