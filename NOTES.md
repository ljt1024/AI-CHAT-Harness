# AgentForge implementation notes

## Decisions
- Task book v3 takes precedence over older sections of the development plan.
- Import the pinned base locally; retain this repository's origin and document history.
- Tier 1 uses one runtime process; MongoDB is the production persistence backend.
- Restricted host tools default to a dedicated workspace; Docker isolation arrives in T10.
- T15.A1+A2 (ADR-0014): every /api request needs a session; identity comes only from the HttpOnly cookie resolved server-side. scrypt instead of argon2 (no package proxy on the deploy server; the hash carries its own parameters). Ownership is an `owner_id` on every row with (owner_id, id) uniqueness, "" meaning shared-read (only the built-in agent). Mismatches answer 404, never 403. The first account is created explicitly from ADMIN_USER/ADMIN_PASSWORD; owner-less legacy rows bind to it at startup. Origin checks accept X-Forwarded-Host; Vite proxy keeps Host (changeOrigin: false) or every dev write looks cross-origin.
- ADR-0015: the login wall moved to the first turn that needs an account. An anonymous visitor gets its own `guest_` owner id (same ownership filters, nothing downstream changed) and may run GUEST_TURNS real turns, site-wide capped per day; installation routes stay 401. Signing in adopts the guest's transcript; unclaimed trials are pruned after GUEST_RETENTION_HOURS; GUEST_TURNS=0 restores the full wall.

- ADR-0016 (first half of T15.A3): a sandbox lease now carries the account that claimed it and keeps it across `release()`, so knowing a session id no longer reaches another account's container or files; one account may hold `SANDBOX_MAX_PER_OWNER` (default 4) claimed sandboxes; `/health` reports owners as a digest only. Workspace directories stay flat (`sandboxes/<id>`) because a warm container is created before its claimant is known and its bind mount cannot be re-pointed. Encrypted MCP credentials, snapshot ownership and the migration rehearsal are still open.

- ADR-0019: a failed model call gets another chance, but only before the first token. The gateway retries `408/409/425/429/500/502/503/504` and transport errors with capped exponential backoff (honouring `Retry-After`), re-raises everything else at once, and stops retrying the moment a chunk is yielded — a streamed answer is not idempotent, so replaying it would duplicate text for the reader. Provider fallback still runs only after that budget is spent, and still refuses a partial stream. `ModelGateway()` defaults to zero retries so test doubles keep failing fast; `create_app` passes the configured budget in. The UI keeps a labelled retry button on an errored bubble, outside the footer that is hidden on error — the button used to vanish exactly when it was needed.

- ADR-0020: the workspace now accepts files from the reader, and the bytes live outside it. Uploads are stored as blobs under `_uploads/<session>/` with a `session_files` row per file, then copied into whichever workspace a turn actually uses (`uploads/<label>`) and announced in the system prompt — a model that is not told about the file answers "I cannot see uploaded files" with the file one `read_file` away. The copy is one-way: the blob is the reader's file, so an `rm` inside a container cannot destroy what they uploaded. Files belong to the conversation rather than the message, so one upload serves every later turn, survives a failed turn and a reload; attaching one therefore also selects agent mode, because the plain completion path has no tools and uploading into a mode that ignores the file is worse than refusing it. Nothing about the request is trusted: the client filename only becomes a display string and a sanitised label, the blob is named from `os.urandom` and created `O_CREAT|O_EXCL|O_NOFOLLOW` at 0600, the extension allowlist omits SVG and executables, leading bytes are checked against the extension for PDF/images/zip/Office, the body is read in 64 KB chunks against a byte budget with a `Content-Length` gate in middleware ahead of Starlette's spool, and every row is fetched in the caller's owner scope with `sessionId` matched (a foreign or mismatched id is the same 404). Guests are refused outright — a guest owner id is free to mint, so a writable disk would be a denial-of-service entry.

- ADR-0004 addendum: a session grant is no longer MCP-only. `_confirm` used to answer `rememberable` from `tool.source == "mcp"`, so a host `run_command` or a `write_file` interrupted the run on every single call with no way to stop it — and the reader's answer was to click through twenty prompts without reading them, which is worse than one extra confirmation. Any tool that reaches the gate can now be remembered, as a **tool name only** (never a set of arguments), in memory, for that conversation. What still holds the line: a policy `denial` is decided before `remembered` is consulted, so a forbidden call stays forbidden no matter what the human granted; the agent's own confirm level keeps applying to every call; and nothing is persisted, so a restart or a new conversation asks again. 453 backend tests pass (the old "host shell cannot be granted" test is now its opposite, plus a new one proving a remembered tool still obeys a denial).

## Backlog
- Session files are re-copied into the workspace on every turn (bounded by the 200 MB account quota), and the quota check is read-then-write, so two simultaneous uploads can overshoot by one file. Deploying the feature needs a reverse-proxy body limit that agrees with `UPLOAD_MAX_BYTES` — nginx's 1 MB default rejects a 25 MB upload with its own error page before the request ever reaches the app.
- Email accounts (ADR-0018) replaced the phone door, but the phone endpoints still exist and the interface no longer offers them. An account created before this change therefore has no way back in from the UI: build a migration path (bind an address from a signed-in session, or an operator-side move) before this reaches real users. Deliverability is now the operator's problem too — SPF, DKIM and a sane From address decide inbox versus spam, and a throttling provider is indistinguishable from a wrong address from the client's side.
- Neither door has a recovery path: a reassigned address or carrier number means a lost account. The daily send counters live in Mongo and the password-failure tracker is per-process, so a multi-instance deployment wants a shared rate-limit store. Consider a second factor or recovery codes before accounts hold valuable data.
- Next platform security milestone (partially done): T15.A1+A2 shipped (ADR-0014) plus the anonymous trial (ADR-0015) and sandbox lease ownership (ADR-0016). Outstanding: per-user workspace roots, encrypted MCP credentials, snapshot ownership, the ownership migration with a dry run and rollback rehearsal, and the two-browser security acceptance (T15.A4) before true multi-user exposure.
- T10-T12: Docker isolation, warm pool, circuit breaker, GridFS snapshots.
- T13-T14: Complete platform endpoints and frontend wizard/approvals/trace/Inspector. The agent wizard and conversation binding shipped 2026-11-02; the standalone trace page/replay, DevTools event stream and per-conversation cost display are still open.
- Legacy MCP ownership: rows written before accounts existed carried an empty owner and were treated as shared, so the config refresh added owned twins with the same id — two rows, double discovery, double tool registration. Startup now settles them onto the operator account (ADMIN_USER, else the first account) and `run_servers` dedupes ids; keep that rule in mind before adding another auto-attach path.
- T15-T20: Skills, delegation, benchmark suite, hardening, full-stack deployment.
